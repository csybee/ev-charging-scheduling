# 数据说明

## 1. 内部数据结构

全仓库统一使用"车辆列表 + 场景配置"两样东西描述问题。

**车辆对象**（`src/data/scenario.py` 与 `src/data/loader.py` 的输出格式）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | int | 车辆编号，从 0 开始 |
| `kind` | str | 车辆类型：`commute` 通勤车 / `visitor` 短停访客车 / `file` 从文件导入 |
| `arr_slot` | int | 到达时段（0-95） |
| `dep_slot` | int | 离开时段（0-95，不含该时段） |
| `need_kwh` | float | 需要充入的电量 |

**场景配置**（`src/config.py` 中的 `DEFAULT_SCENARIO`）：

| 键 | 含义 | 默认值 |
|---|---|---|
| `n_cars` | 当日需要充电的车辆数 | 40 |
| `n_stalls` | 充电桩数量 | 16 |
| `stall_power_kw` | 单桩额定功率 | 11.0 kW |
| `transformer_kw` | 变压器容量上限 | 100.0 kW |
| `pv_peak_kw` | 光伏装机容量 | 100.0 kWp |
| `mean_need_kwh` | 单车平均充电需求 | 16.0 kWh |
| `seed` | 随机种子 | 20261031 |

## 2. 赛前场景的合成方式

赛前拿不到主办方的真实充电数据，因此按公开的出行统计规律合成场景：

- **通勤车（约 75%）**：早高峰陆续到达（08:30 前后），傍晚离开（17:30 前后）。停留时间长、调度弹性大。
- **短时访客车（约 25%）**：白天随机到达，停留 1–4.5 小时。时间紧、必须优先满足。

两种车的混合比例是关键——它同时制造了"可平移的弹性需求"和"不可平移的刚性需求"。只有同时照顾这两类车的策略才是可用的策略。

生成逻辑见 `src/data/scenario.py`，随机数由 `src/rng.py` 中的显式线性同余发生器产生，**同一个种子在任何 Python 版本上都会得到逐位相同的结果**。

## 3. 接入官方数据

主办方给出的充电数据格式要到赛时才公开。为此 `src/data/loader.py` 实现了一个容错性较强的 CSV 导入器。

**使用方式**：

```bash
python run_experiment.py --data 场站数据.csv
```

或在代码中调用：

```python
from data.loader import load_cars_from_file

cars, stats = load_cars_from_file("场站数据.csv", cfg)
```

**推荐的列格式**（见 `examples/车辆数据示例.csv`）：

```csv
车辆编号,到达时间,离开时间,需求电量kWh
1,08:12,17:40,14.5
2,08:31,18:05,21.0
```

**容错规则**：

| 情况 | 处理方式 |
|---|---|
| 表头为中文或英文 | 都能识别（到达 / arr / start、离开 / dep / end、电量 / kwh / energy …） |
| 列顺序不同 | 按表头关键词定位；识别不出的列按"第 2、3、4 列"兜底 |
| 没有表头 | 直接按"第 2、3、4 列"解析 |
| 时间写成 `08:30` | 解析为 8.5 小时 |
| 时间写成 `8.5` | 解析为 8.5 小时 |
| 某行字段缺失或非法 | 跳过该行并计数，不影响其余数据 |
| 需求量超过停留时间内物理可充上限 | 按上限截断并计数 |

导入后 `stats` 会给出清洗统计（总行数 / 有效车辆 / 跳过行数 / 按上限截断），建议在实验报告中如实披露——数据清洗过程本身就是"数据处理"模块的工作成果。

## 4. 能源模型假设

以下三个模型在赛前是**假设值**（见 `src/config.py`）。赛时若主办方给出真实数据，只需替换这三个函数，其余模块无需改动。

**分时电价** `price_at(hour)`，单位 元/kWh：

| 时段 | 电价 | 时段类型 |
|---|---|---|
| 21:00–08:00 | 0.35 | 谷 |
| 08:00–11:00 | 1.05 | 峰 |
| 11:00–13:00 | 1.25 | 尖峰 |
| 13:00–17:00 | 0.65 | 平 |
| 17:00–21:00 | 1.05 | 峰 |

注意 11:00–13:00 是**尖峰**——这恰好是光伏出力最强的时候，于是"最便宜"和"最绿"产生了冲突。这个设定是有意为之：它让"只按电价调度"和"按碳强度调度"产生可观察的差异。

**电网碳强度** `carbon_at(hour)`，单位 kgCO₂/kWh：

| 时段 | 碳强度 | 说明 |
|---|---|---|
| 00:00–07:00 | 0.80 | 夜间以煤电为主 |
| 07:00–11:00 | 0.65 | 早高峰爬坡 |
| 11:00–15:00 | 0.35 | 光伏大发，全网碳强度最低 |
| 15:00–18:00 | 0.55 | 光伏回落 |
| 18:00–21:00 | 0.70 | 晚峰，煤电调峰 |
| 21:00–24:00 | 0.75 | 夜峰 |

**光伏出力** `pv_at(hour, pv_peak_kw)`：06:30 开始发电，12:30 前后达到装机容量对应的峰值，18:30 停止。曲线形式为 $\sin^{1.6}$，比标准正弦更接近实际出力形状（中午平台更平坦）。

## 5. 指标定义

见 `src/metrics/evaluate.py`。其中两个容易被误解的指标需要说明：

**光伏就地消纳率**：充电负荷实际用掉的屋顶光伏电量，占当天光伏总发电量的比例。剩余部分被视为上网，不计入本项目的收益。

$$\text{消纳率}=\frac{\sum_t\min(L_t,\ PV_t)\Delta t}{\sum_t PV_t\Delta t}$$

**电费与碳排只对电网购电量 $G_t$ 计算**，自发自用的部分既不计费也不计碳。这一定义决定了"把充电挪到光伏大发时段"同时改善经济性和碳排放两个目标。

**变压器过载时长**：负荷超过变压器容量的时段数乘以 0.25 小时。基线的过载是真实风险——实际运行中会触发变压器保护。
